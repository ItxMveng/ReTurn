⚡ FAST PATH — Flux Optimisé Sans Friction

Principe fondamental Un utilisateur qui galère abandonne. Chaque étape supplémentaire coûte ~20% d'utilisateurs. Le Fast Path impose : déclaration en < 60 secondes, restitution en 3 actions. La sécurité s'adapte au score de confiance, pas l'inverse.

BUGS CRITIQUES ET CORRECTIONS

🔴 BUG P0 — Déclaration non passée à status="matched" (matching_service.py)
  • Après db.flush() sur le match créé, les deux déclarations restent à status="active".
  • Conséquence : nouveaux matchs redondants créés, état incohérent.
  • Fix : ajouter decl_found.status = "matched"; decl_lost.status = "matched" après le flush.
🔴 BUG P0 — Profil impossible à compléter (profile_page.dart)
  • is_profile_complete requiert date_of_birth + gender mais le formulaire ne les affiche pas.
  • Le badge "Incomplet" ne disparaît jamais → frustration utilisateur.
  • Fix : ajouter DatePicker pour date_of_birth et Dropdown pour gender dans _EditProfileSheet.
🔴 BUG P0 — Vérification auto-approuvée sans contrôle (verification_page.dart)
  • Upload du selfie → status = "approved" immédiatement, sans comparaison ni revue.
  • N'importe qui connaissant le nom peut se faire passer pour le propriétaire.
  • Fix : implémenter la vérification adaptative par niveau (voir section Fast Path).
⚠ BUG P1 — Refresh token non implémenté (auth_notifier.dart)
  • Expiration de l'access_token → déconnexion brutale sans tentative de renouvellement.
  • Fix : intercepteur Dio : si 401 → POST /auth/refresh → rejouer la requête originale.
⚠ BUG P1 — Nommage ambigu confirmed_by_* (match.py vs restitution.py)
  • Les deux modèles ont des champs confirmed_by_owner et confirmed_by_finder avec des sémantiques différentes.
  • Fix : Match → accepted_by_owner/finder · Restitution → handoff_confirmed_by_owner/finder.
⚠ BUG P1 — serverClientId hardcodé (auth_notifier.dart ligne 138)
  • '774092129161-ed0d2cs235cccvbsu506ikdiehktpko7.apps.googleusercontent.com' en clair dans le code.
  • Fix : déplacer dans flutter_dotenv ou AppConfig chargé depuis un fichier d'env non commité.
💡 AMÉLIORATION P2 — Compteur déclarations actives visible
  • La limite ACTIVE_DECLARATIONS_LIMIT = 3 est appliquée silencieusement (HTTP 429).
  • Amélioration : afficher "2/3 déclarations actives" dans l'UI avant soumission + rendre la limite configurable côté admin.
💡 AMÉLIORATION P2 — Admin panel avec données réelles
  • L'admin HTML actuel affiche des données mockées, pas de vraies API calls.
  • Fonctionnalités manquantes : file vérifications, modération signalements, gestion zones, audit log.
  • Plan : connecter les vrais endpoints /api/v1/admin/*, ajouter les sections manquantes.
